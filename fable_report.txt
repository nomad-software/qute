I ran probes in a scratch module outside the repo, under ASan.

- QTextTableCell segfaults after its document is collected. Take a cell from cur.InsertTable(2, 2).CellAtWithCol(1, 1), drop the document, GC, then call cell.RowSpan(): SEGV in QTextTableCell::format().
- QTextBlock reads freed memory. b := doc.Begin() gives "hello" before; after the document is collected or Delete()d, b.IsValid() is still true and b.Text() returns "". There is no crash and no panic. ASan stays silent because Qt itself is not instrumented, so calling this a use-after-free is my reading of the changed output.
- QWidgetItem is probably the same. NewQWidgetItemWithWidget(w) has no keep rule; after a GC, SizeHint() returned 0x0 without a crash. I did not confirm the widget had actually been freed.
- The QDataStream skip message points at a class that is not bound. It says to use NewQDataStreamWithIODevice over a QBuffer, but there is no QBuffer binding, so there is currently no in-memory writable stream.

QTextBlock and QTextTableCell need the same depends-on treatment QModelIndex got; today only QModelIndex has it.
